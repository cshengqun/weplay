# 产品功能探索报告 · 2026-10-02

> 本期主题：**「让第一批人真正用起来」——冷启动、新手引导与增长回流闭环**。前五期已把一场球的赛前（v1.17）、赛中（v1.18）、赛后（v1.16）功能蓝图铺满，但这些迭代尚未动工、产品也还没有稳定的真实用户。功能再多，决定成败的是：**组织者能否 3 分钟办成第一场球、球友报名后是否愿意再打开**。本期补齐这块「非功能功能」。

> 报告人：产品经理（定时任务自动产出）｜项目：球局轮转 weplay（当前版本 **v1.15.1**）

## 一、现状盘点：增长链路上的断点（基于当前代码）

| 环节 | 现状 | 断点 |
|---|---|---|
| 入口结构 | tabBar 仅「首页 / 发起球局 / 排行榜」 | **没有「我的」一级入口**，球友看不到自己的球局/战绩/段位，v1.16 个人主页将无处安放 |
| 首次使用 | 首页即球局列表；发起页一次性暴露名称/日期/开始/时长/场地数/场馆/场地备注等字段 | 新组织者无引导、无模板，学习成本高；空首页未见明确引导 CTA |
| 分享 | 6 个页面都有 `onShareAppMessage` | 标题是静态通用文案（「球局轮转」「在线报名、轮转…」），**没有「X 人已报名/我升段了」等社交钩子** |
| 回流 | 已有订阅消息骨架（v1.15.1 `notify.js`，模板 ID 待申请） | 球友报名后无主动触达，开赛前/出轮转/出分全靠群里喊；通知触发点未系统化 |
| 榜单 | 全国段位榜（rank） | 冷启动期榜单稀疏，新用户看不到「段位」的意义；定级中（前 5 场）无进度提示 |
| 空状态 | 无球局/无战绩/未定级缺少成体系的引导 | 用户容易在空白页流失 |

**核心判断**：排位、个人主页、地区榜都是数据/网络效应型功能，没有第一批活跃球局就是空的。当前最该做的不是再堆模块，而是打通**最小成功闭环**并降低两端门槛。

**定义 aha moment（北极星）**：一个组织者在小程序里完成「建局 → 分享到群 → ≥4 人在线报名 → 生成轮转 → 打完记分确认 → 大家看到积分/段位」，并在**下周再办一场**。建议北极星指标＝**每周完整跑通的球局数**，次北极星＝组织者次周复办率（指标与阈值待真实数据验证）。

## 二、功能清单（场景 / 价值 / 数据 / 思路 / 风险 / 优先级）

### N1. 首页角色分流与两条路径 — P0

- **场景**：组织者和球友打开小程序目的完全不同（办球 vs 找球/看排名）。
- **价值**：3 秒内让不同角色找到动作，降低首屏流失。
- **功能描述**：无球局的新用户首页展示两个主按钮「我要组织球局」「我来报名/看排名」；有球局后首页回归「最近球局 + 进行中比赛」列表。组织者路径突出发起与分享，球友路径突出「分享给我的球局」与排行榜/我的。
- **数据关系**：纯前端，本地 storage 记 `roleHintSeen`；不新增集合。
- **风险**：老用户不应被强制选择——仅在空状态/首次出现，可跳过。

### N2. 创建向导化 + 球局模板 + 记住上次设置 — P0

- **场景**：固定球局几乎每周相同（周三 20:00–22:00、2 片场、双打、21 分），现在每场重填。
- **价值**：把「发起一场球」从填一张大表降到「一键套用 → 改日期 → 分享」。
- **功能描述**：
  - 提供常用模板（双打娱乐局 / 混双局 / 单打练习 / 自定义），预填时长、场地数、目标分、轮转类型；
  - 「再来一局」：从历史球局一键复制配置（复用已有 activity 数据，仅改日期）；
  - 记住该组织者上次设置（本地 storage + 可选 me 偏好）。
- **数据关系**：activities 现有字段足够；模板为前端常量；偏好存本地或 `me.prefs`。
- **风险**：不要把向导做成强制多步——熟练组织者应能直接在原表单快速填写，向导与表单可切换。

### N3. 「我的」一级入口（tabBar 第 4 项）— P0，v1.16 前置

- **场景**：球友要找自己的报名、战绩、段位、成就。
- **价值**：个人数据是排位体系的留存钩子，没有稳定入口等于白做；也是订阅授权、战绩认领、地区设置的收纳处。
- **功能描述**：tabBar 增加「我的」，聚合：身份卡（头像/段位，点进 v1.16 个人主页）、我报名的球局（`getJoinedActivities` 已有）、我组织的球局、我的战绩/成就入口、消息与设置（订阅授权、隐私、地区）。
- **数据关系**：消费 me、rank、activities；个人主页仍为 v1.16 的 `pages/profile`，本页是入口聚合。
- **风险**：tabBar 最多 5 项，现 3 项，加到 4 项无压力；未登录（无 openid）时展示「点我绑定微信档案」引导。

### N4. 关键节点动态分享卡片 — P1

- **场景/价值**：分享是小程序唯一的零成本拉新通道，应在用户最想炫耀/最需要凑人的时刻自动带钩子。
- **功能描述**（改造现有 6 处 `onShareAppMessage`，成本低）：
  - 创建后/报名中：「{球局名} 已报 N 人，还差 M 人开打，点我报名」；
  - 出轮转后：「今晚 8 点开打，来看看你的对阵」；
  - 结算/升段后（依赖 v1.16）：「我刚升到 {段位}，ELO {分数}，来挑战」；
  - 战报卡（v1.16 F7）：「本场我 {胜负}，ELO ±N」。
- **数据关系**：读 activity.players、rotation、rank；纯展示，无新写。
- **风险**：自定义分享图（imageUrl）需 canvas 出图，MVP 先用动态标题 + 默认图；标题长度与表情克制。

### N5. 订阅消息「通知触发点地图」（回流核心）— P1

- **场景/价值**：一次性订阅消息是球友报名后唯一的主动回流手段，应在每个「用户刚表达关心」的动作处请求授权，并在对应事件下发。
- **完整触发点（建议模板位，复用 v1.15.1 `notify.js`）**：
  | 事件 | 模板位 | 请求授权时机 | 依赖 |
  |---|---|---|---|
  | 球局明天开打 | `remind` | 报名成功时 | 现有 |
  | 轮转已生成/对阵出炉 | `rotationReady` | 报名/进分享卡时 | rotation |
  | 轮到你上场（下一轮） | `nextRound` | 签到/到场时 | v1.18 大屏/轮次 |
  | 有比分待你确认 | `pendingConfirm` | 报名/上场后（已接） | v1.14 |
  | 比分被异议 | `dispute` | 提交比分时（已接） | v1.14 |
  | 已结算/ELO 涨降、升段 | `settled` | 报名/确认后（已接） | v1.15 |
  | 候补转正 | `waitlistPromote` | 加入候补时 | v1.17 |
  | 签到开启 | `checkIn` | 报名时 | v1.17 |
  | 费用催缴 | `fee` | 签到/赛后 | v1.17 |
- **实现要点**：微信一次性订阅「授权一次发一条」，需在对应动作 `requestSubscribeMessage`（join.js 已接 pendingConfirm/settled，按此模式扩展）；云函数在事件点调用 `sendSub`；模板未申请前全部静默降级。
- **风险**：不能滥发导致用户取消授权；每事件一条、措辞带具体球局名与时间；模板 ID 与字段需在 mp 后台申请后回填（沿用 v1.15.1 遗留）。

### N6. 成体系的空状态设计 — P1

- **场景**：首页无球局、榜单无人、个人无战绩、尚未定级。
- **价值**：把「空白页流失」变成「引导下一步」。
- **功能描述（每处给文案 + 单一主 CTA）**：
  - 首页无球局：「还没有球局，发起第一场 / 找球友要分享卡」；
  - 排行榜人少：「先打完一场定级赛，你就是榜单第一批人」+ 如何开始；
  - 个人无战绩：「报名并打完一场球，这里会记录你的成长」；
  - 无云开发：保留现有「见 README」提示，升级为图文开通指引。
- **风险**：纯前端，低风险；文案避免制造虚假繁荣。

### N7. 定级进度引导 + 空窗期「身边榜」（排位章节，见第三节）— P1

### N8. 组织者裂变与复办工具 — P1

- **功能描述**：
  - 「一键复制报名接龙文案」：自动生成含时间/地点/人数/小程序路径的接龙话术，方便发群；
  - 「最近球友快捷再邀」：新建球局时可快速拉取上一场参与者名单预填/提醒；
  - 球局结束页放「再来一局」（与 N2 复用），把复办成本降到最低。
- **价值**：组织者复办是留存的核心，复办时凑人最快。
- **数据关系**：读历史 activities.players；无新集合。
- **风险**：不做未经授权的主动推送骚扰；快捷再邀仅对组织者本地/其创建的球局生效。

### N9. 新手容错与轻教学 — P2

- 删除球局/清空名单二次确认（已具备）；首次生成轮转给一句「锁定后可在记分页调整」提示；关键破坏性操作可撤销提示；3 张滑动说明（报名—轮转—记分）首次进入展示，可跳过。纯前端、本地标记。

## 三、排位体系：冷启动期 / 定级期体验（规则不变，补「空榜期」设计）

全国 ELO + 段位 + 定级 + 确认/超时结算规则已在 v1.15 上线（详见 09-25 报告），地区榜按 09-30 后置。本期只解决**空榜期排位不劝退**：

1. **定级进度显性化（N7）**：新球友前 5 场为定级赛，个人卡/榜单显示「定级中 2/5，再打 3 场显示段位」，避免「我为什么没段位/没上榜」的困惑。数据现成（rank.placed、counts）。
2. **空窗期用「身边榜」替代全国榜的竞争感**：全国榜人少时，排行榜页优先展示**与「我」相关的小榜**——我参与过的球局战绩榜、常打的球友榜（按共同参与/同一组织者过滤，复用 `score.computeTotal` 与 activities 数据，密度无关）。全国榜作为顶部 tab，人多后自然成为主角。
3. **冷启动红线（防刷与诚信）**：**不得用虚拟机器人/假数据填充全国榜**，宁可展示空状态引导；组织者自测球局可标记为「练习局」不计段位（建议给 activity 增加 `casual` 布尔，练习局只出轮转/积分、不结算 ELO——此项为 P2，需同步在结算处过滤）。
4. **地区榜上线门槛**：待某省/市活跃球局与定级人数达到阈值后再开放该地区榜（具体阈值待验证），避免上线即空榜；地理字段继续通过 v1.17 场馆定位预埋。
5. **赛季/软重置**维持 v1.20 规划，冷启动期不启动赛季，避免早期用户段位被频繁重置。

## 四、冷启动落地路径（给项目负责人，非代码）

1. **种子场景**：先在你自己的固定球群完整跑 3–5 场，验证「建局→报名→轮转→记分→出榜」无卡点，把高频组织者的反馈作为 v1.16–v1.18 排序依据。
2. **每个球局结束即引导复办与分享**：结算页是情绪最高点，放「再来一局」「晒段位/战报」。
3. **建议观测漏斗**（事件埋点可后续补，先手工/云函数日志估算，阈值待验证）：
   打开 → 发起球局完成率 → 分享后报名转化率（人数/访问）→ 轮转生成率 → 记分确认完成率 → 7 日内复办率、球友 D7 回流。
4. **并行原则**：体验与增长项（N1/N2/N3/N6）成本低、见效快，建议**与 v1.16 同期或先于部分功能上线**；通知（N5）随各功能点逐步申请模板。

## 六、本期 Top3 推荐

1. **N3「我的」一级入口 + N7 定级进度（与 v1.16 绑定）**
   理由：排位和个人数据是最强留存钩子，但当前 tabBar 没有「我的」，球友打完一场后找不到自己的段位和战绩，钩子直接落空。这是 v1.16 的**前置条件**而非可选项，顺手把「定级中 2/5」做显性化，消除新用户最大困惑。

2. **N2 创建模板 / 记住上次设置 / 再来一局**
   理由：供给侧（组织者）决定平台有没有球局。固定球局每周配置几乎相同，把发起成本从「填一张大表」降到「一键复制改日期」，直接提升北极星「次周复办率」；纯前端、读现有数据、风险极低。

3. **N5 订阅消息触发点地图（先补开赛前/轮转/出分三个最高频）**
   理由：球友报名后目前没有任何主动回流手段，是增长漏斗最下游的硬断点。骨架已在 v1.15.1 就绪，只需按地图申请模板、在报名/签到动作处请求授权，即可把「轮转好了、该你上场、出分了」变成自动召回，投入小、对回流最直接。
