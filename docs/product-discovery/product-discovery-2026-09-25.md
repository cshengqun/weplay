# 产品功能探索报告 · 2026-09-25

> 本期主题：**从「轮转记分工具」到「羽毛球排位平台」**——以王者荣耀式段位/榜单为增长引擎，补齐信任、数据与地区体系。
>
> 报告人：产品经理（定时任务自动产出）｜项目：球局轮转 weplay（当前版本 v1.13.3）

---

## 一、现状盘点

### 1.1 已具备能力

| 模块 | 现状 |
|---|---|
| 球局管理 | 新建/删除球局，字段含名称、日期、开始时间、时长、场地数、场馆、场地备注 |
| 报名管理 | 姓名 + 性别 + 中羽 1–9 级水平；云开发在线报名；OpenID 档案（me 集合，跨设备） |
| 轮转生成 | 单打/双打/混双，圆桌轮转法，自动/自定义轮数，公平性贪心，预览确认锁定 |
| 比分录入 | 目标分 11/15/21/自定义，实际比分录入，自动标识胜方 |
| 单局积分榜 | 胜 +2 / 负 +1，按 胜场→胜率→姓名 排序，并列名次 |
| 跨球局总榜 | 云端全量球局（上限 500 场）聚合，Top50，按 OpenID 合并同一人 |
| 分享协同 | 分享微信群、在线报名、结果云端同步 |

### 1.2 数据模型（现状）

- **activities 集合**：`{ _id, _openid(创建者), name, date, startTime, durationHours, courts, venue, courtText, done, players:[{id,name,gender,level,avatar,openid}], rotations:{singles,doubles,mixed} }`
- **rotation 快照**：`{ players:[快照], rounds:[{no, matches:[{court, teamA:[idx], teamB:[idx]}]}], scores:{'轮-场':{sA,sB}}, confirmed, stats, totalMatches }`
- **me 集合**：`{ _openid, nickname, avatar, gender, level }`

### 1.3 关键缺口（走向排位平台的拦路问题）

1. **积分规则不具备排位属性**：负场也 +1 分，"打得久 = 排名高"，无法衡量真实水平，且没有段位目标感。
2. **结果真实性无保障**：比分由组织者单方录入，没有对手确认；在"所有用户可读写"权限下，理论上可随意造数据——排位体系一旦上线，刷分即崩盘。
3. **无地区维度**：me 档案没有地区字段，无法做省/市/区榜。
4. **无赛季与成长闭环**：没有赛季重置、段位继承、历史回溯，长期缺乏追求。
5. **个人数据单薄**：只有场次/胜率，没有分项战绩、成长曲线、成就、比赛历史。
6. **写入在小程序端**：全国榜、ELO 结算等强一致逻辑放在客户端既不安全也撑不住量，需要云函数承接。

## 二、标杆与竞品洞察

### 2.1 王者荣耀排位体系（2026 S43，对标基准）

- **8 大段位 + 星级**：倔强青铜(3 小段×3 星) → 秩序白银(3×3) → 荣耀黄金(4×4) → 尊贵铂金(4×4) → 永恒钻石(5×5) → 至尊星耀(5×5) → 最强王者(0 星起) → 传奇王者(100 星+)。
- **王者细分称号**：0–9 入门 / 10–19 至圣 / 20–29 无双 / 30–39 非凡 / 40–49 绝世 / 50–99 荣耀 / 100+ 传奇。
- **保护机制**：勇者积分掉星保护，失败时用积分抵扣星级，降低挫败感。
- **荣耀战力 + 地区称号**：初级荣耀(区级,战力≥1000) / 中级(市级≥2000) / 高级(省级≥3000) / 国服最强(全国≥4000)；榜单按战力排名。
- **赛季继承**：每赛季按上赛季段位降级继承（如王者继承到星耀/钻石），保证新赛季有重新攀登的动力。
- **天梯榜**：地区前 100 名展示，是高手的身份标杆。

### 2.2 羽毛球/拍类竞品要点

| 产品 | 值得借鉴 |
|---|---|
| 铭心乐Go | 附近场馆实时状态/价格、视频 + AI 技术点评、战绩积分 |
| 羽聚时刻 | 俱乐部权限管理、活动自动对阵、实时消息、按项目分类的胜率榜、水平智能推荐 |
| 羽Rank | 拉人/排阵/记分/回看一体化，强调"成长阶段"可视化 |
| QourtPlay | **结果须所有参与者确认后才记录**（共识机制）；多拍类运动 |
| 球局掌 | 全国场馆预订、多人拼场分摊费用、多赛制业余赛事、球友匹配 |
| 行动榜 | 专业记分器（自动选边/换位）、签到/记账/物料管理、球队数据 |
| Play Engine | 共识投票记分、实时榜、**TV 投屏模式**、持久群组 |
| 羽宙无敌 | **成绩需对手自主报名确认**、每周一评级、约战发帖 |

**结论**：我们的轮转算法 + 确认锁定流程已是行业中上水平，**真正的差异化机会是"可信的段位 + 全国/地区榜单"**——多数竞品只做了胜率榜，没人把王者式段位、地区称号、赛季闭环做透。

## 三、重点设计：全国排位体系

### 3.1 设计原则

- **星级为表，ELO 为里**：用户看到的是段位 + 星级（直觉、有目标），底层用 ELO 等级分结算（公平、抗刷）。
- **综合段位 + 分项战力**：对标王者"段位 + 分路战力"，一个综合段位，单打/双打/混双各有分项 ELO。
- **信任先行**：没有"对手确认"就没有排位分。

### 3.2 段位设计（羽毛球化命名）

| 大段位 | 小段×星数 | 对应 ELO 区间（建议初值） | 规则 |
|---|---|---|---|
| 青羽 | 3×3 | 900–1049 | 失败不掉星（新手保护） |
| 白羽 | 3×3 | 1050–1199 | 失败不掉星 |
| 金羽 | 4×4 | 1200–1399 | 开始掉星 |
| 翡翠 | 4×4 | 1400–1599 | — |
| 钻石 | 5×5 | 1600–1849 | 解锁巅峰/赛事资格 |
| 星耀 | 5×5 | 1850–2099 | — |
| 最强球王 | 0 星起 | 2100+ | 按星给细分称号 |
| 传奇球王 | 100 星+ | 顶部 | 全服展示 |

球王细分（对标王者）：0–9 星「新锐球王」/10–19「至圣球王」/20–29「无双球王」/30–39「非凡球王」/40–49「绝世球王」/50–99「荣耀球王」/100+「传奇球王」。

> ELO 区间为建议初值，上线后按全服段位分布目标（如钻石以上 ≤15%）定期校准。

### 3.3 ELO 结算引擎（核心算法）

- 初始 ELO：**1000**；前 5 场为定级赛，K 值加倍（K=48），快速收敛；定级后 K=24，球王以上 K=16（高分段更稳定）。
- 单场预期胜率：`EA = 1 / (1 + 10^((RB-RA)/400))`；得分变化：`Δ = K × (实际结果 − 预期)`。
- **双打/混双**：队伍 ELO = 两人 ELO 均值；按队伍胜负结算，两人各自按个人 ELO 与队伍预期计算 Δ（天然实现"带新手赢强队涨分多、抱大腿赢弱队涨分少"）。
- **分项 ELO**：单打/双打/混双独立累计。
- **综合 ELO**：`0.4×单打 + 0.3×双打 + 0.3×混双`（未打的项不计入，按已打项归一化权重）；综合 ELO 映射段位与星级。
- 星级由综合 ELO 在段位内的位置换算，升段/降段随 ELO 跨区间自动发生。
- **保护分（对标勇者积分）**：每参赛一场获得少量"拼搏分"（胜负都给，连胜/MVP 加成），累积可抵扣一次掉星，降低挫败、鼓励参赛。

### 3.4 定级与历史回溯

- 新用户：ELO 1000 起步，打满 5 场定级赛后显示段位。
- 自报中羽等级（zy1–9）仅作为**初始 ELO 建议**（如 zy5 ≈ 1300），但必须经过 5 场验证，实测偏差大则快速修正——防止虚报水平。
- 老用户/手动录入球员：用现有已录比分**回溯 ELO**（按时间顺序重放全部比赛），一次性生成初始段位；无 OpenID 的球员仍按姓名聚合，引导其认领绑定。

### 3.5 防刷分机制（P0，决定排位生死）

1. **对手确认才计分**：比赛结果由双方（双打为四人）在小程序内确认后才进入 ELO 结算；有一方未确认的比赛挂"待确认"，超时（如 48 小时）默认生效但可申诉。对标 QourtPlay / 羽宙无敌 / Play Engine。
2. **同对手收益递减**：两名玩家每日前 2 场正常计分，第 3 场起 ELO 收益按 50%、25% 递减，防止互刷。
3. **有效比赛门槛**：球王以上升星要求对手平均 ELO 不低于自身 200 分以内；碾压局（预期胜率 >95%）收益趋近于 0。
4. **异常检测**：异常比分（如大量 21:0）、短时高频比赛、同设备/同群闭环比赛自动标记，进入人工/规则复核。
5. **结算上云函数**：ELO 计算与写入在云函数完成，客户端只提交结果与确认，无法直接改分。
6. **赛季适度重置**：抑制历史刷分存量。

### 3.6 与现有"胜+2/负+1"的衔接

- 旧积分榜**保留为"球局积分榜"**（单局内仍用，便于当场看排名）。
- 新增 `utils/rank.js` 承载 ELO 引擎；总榜切换为 ELO 段位榜，旧积分不再作为跨球局排名依据。
- 老数据通过回溯脚本迁移，不丢战绩。

## 四、重点设计：地区排位体系

### 4.1 地区归属

- me 档案新增 `region: { province, city, district, adcode }`。
- 首次进入排位时引导选择：可用 `wx.getLocation`（需地理位置授权）+ 微信逆地理**建议**，用户确认；也支持手动选择。
- **防窜区刷榜**：地区 30 天内仅可修改 1 次，修改后地区战力冻结 7 天；榜单按"常驻地"结算（对标王者地区称号的归属逻辑）。

### 4.2 榜单层级与称号（对标荣耀战力）

| 层级 | 称号 | 最低战力门槛（建议） | 上榜规则 |
|---|---|---|---|
| 区级 | 区级高手 | 战力 ≥1000 | 区榜前 100 |
| 市级 | 市级名将 | 战力 ≥2000 | 市榜前 100 |
| 省级 | 省级强手 | 战力 ≥3000 | 省榜前 100 |
| 全国 | 全国百强 / 国服最强 | 战力 ≥4000 | 全国榜前 100 |

- **战力值**（对标荣耀战力）= 综合 ELO + 近期表现分（近 20 场胜率/连胜）+ 参赛活跃分；长期不打会衰减，促使持续活跃。
- 榜单**每日凌晨由定时云函数刷新**（对标羽宙无敌每周一评级、王者每周结算），展示前 100 名 + 本人排名。
- 称号在个人主页、比分页、分享卡片展示，是社交货币。

### 4.3 与全国榜的关系

- 全国榜按综合 ELO 排名（实力绝对排序）；地区榜按战力在本地区排名（相对 + 活跃）。
- 一个玩家可同时拥有段位、全国排名、地区称号，三者展示在同一主页。
- 扩展维度（后续）：球馆榜、俱乐部榜、高校榜。

### 4.4 赛季机制

- 每 **3 个月一赛季**；赛季末结算榜单、发放限定称号/徽章。
- 段位继承对标王者：高段位按规则降级（如球王继承到星耀/钻石，对应 ELO 软重置向均值回归），保留"底子"但需要重新攀登。
- 历史赛季榜单与个人赛季回顾可查（"S1 赛季我是深圳市第 23 名"）。

## 五、其他功能建议清单

> 优先级：P0 必做（排位地基）/ P1 重要（差异化与留存）/ P2 可探索（增量与商业化）。

### 5.1 主流程深化

**F1. 比赛结果多方确认机制 — P0**
- 场景：组织者录入比分后，球友收到"待确认结果"。
- 价值：排位信任的地基，杜绝篡改与刷分。
- 数据：match 增加 `confirmedBy:[openid]`、`confirmStatus`、`dispute`；新增订阅消息提醒。
- 思路：录入后推送订阅消息 → 各方确认 → 云函数结算 ELO；争议进入复核。
- 风险：熟人嫌麻烦 → 默认"超时自动生效"，只在有异议时拦截。

**F2. 云函数化与数据权限收紧 — P0**
- 价值：排位/榜单强一致、防改分的前提。
- 内容：activities/me 改为云函数写入（客户端不再直写），新增结算云函数、榜单聚合定时云函数。
- 风险：改造量较大，需兼容未开通云开发的单机模式（保留本地降级）。

**F3. 候补 / 排队 / 请假 — P1**
- 场景：报名满员后可候补，有人请假自动递补；开场前请假释放名额。
- 价值：解决约球最常见的"鸽子"痛点。
- 数据：player 增加 `status: signed|waitlist|leave`、候补序号。

**F4. 签到与开场核对 — P1**
- 场景：到场扫码/一键签到，未签到者不进入轮转，临时现场加人。
- 价值：名单与实际到场一致，轮转更准；行动榜等竞品的成熟功能。

**F5. 费用 AA / 记账 — P1**
- 场景：录入场地总费用，按人数（可区分到场/会员）平摊，生成缴费清单与状态。
- 价值：组织者高频刚需；行动榜、球局掌均有。
- 数据：activity 增加 `fee:{total, rule, paidBy:[openid]}`。

**F6. 正式赛事赛制（小组赛 + 淘汰赛）— P1**
- 场景：俱乐部月度赛，先分组循环、再单败淘汰，自动出签表与名次。
- 价值：承接"认真打比赛"的场景，是高 ELO 玩家的出口。
- 风险：赛制复杂，建议在轮转玩法稳定后再做。

**F7. 现场临时换人 / 弃权处理 — P2**
- 场景：有人临时离场，轮转中替换或判弃权，比分规则明确。

### 5.2 个人统计与数据中心

**F8. 个人主页 / 数据中心 — P0**
- 内容：头像、段位徽章、全国/地区排名、分项战绩、成长曲线、最近比赛、成就、常搭档。
- 价值：数据沉淀与自我驱动的载体，也是段位/称号的展示位；排行榜点击姓名直接进入（替代现在的弹窗）。
- 数据：新增聚合视图，me 扩展段位/地区字段。

**F9. 分项战绩与成长曲线 — P1**
- 内容：单打/双打/混双独立的场次、胜率、净分、ELO 走势（按时间）、连胜连败、最高段位。
- 价值：可视化"变强"，对标羽Rank 的成长阶段。

**F10. 成就 / 徽章体系 — P1**
- 示例：首胜、十连胜、连胜终结者、全勤王、逆风翻盘、混双达人、赛季 X 场。
- 价值：轻量目标感，覆盖排位之外的用户。

**F11. 比赛历史与回看 — P2**
- 内容：每场对阵、比分、搭档/对手、当时 ELO 变化，可分享战报卡片。

### 5.3 组织与社交

**F12. 俱乐部 / 球队 — P1**
- 内容：创建俱乐部、成员权限、俱乐部队标、俱乐部活动与内部榜、俱乐部主页。
- 价值：把零散球局沉淀为稳定组织，是留存与拉新的核心容器（羽聚时刻的主战场）。

**F13. TV / 投屏展示模式 — P1**
- 内容：横屏大字展示当前轮次对阵、实时积分榜/段位榜，适配场馆电视。
- 价值：球馆场景刚需，强化现场仪式感与榜单存在感（Play Engine 已验证）。

**F14. 球友关系与对战邀请 — P2**
- 内容：关注球友、约战、战绩对比、"我和你的交手记录"。

**F15. 约球广场 / 水平匹配 — P2**
- 内容：公开球局大厅，按地区 + 水平 + 时间筛选/推荐，散客可加入陌生人球局。
- 价值：解决"找不到人打"，但需要用户密度，建议有地区数据积累后再做。

### 5.4 场馆、内容与商业化

**F16. 场馆信息与预订导流 — P2**
- 内容：场馆资料、场地数、价格/营业状态，预订跳转或拼场（对标铭心乐Go、球局掌）。
- 价值：高频入口，也是商业化（佣金/广告）来源；数据冷启动重，可先做轻量黄页。

**F17. 视频 / AI 技术点评 — P2**
- 内容：上传打球视频，AI 剪辑高光、给技术建议（铭心乐Go 已有）。
- 价值：内容差异化，但与核心排位链路较远。

**F18. 教学 / 训练内容 — P2**
- 内容：按段位推荐训练计划与教学视频，"上分攻略"。

**F19. 商业化探索 — P2**
- 内容：场馆导流佣金、装备推荐/电商、会员（高级数据/无限俱乐部成员）、赛事报名、品牌赞助榜单。

## 七、本期 Top3 推荐

1. **F1 比赛结果多方确认 + F2 云函数化（信任地基）**
   理由：排位体系的所有价值都建立在"结果可信"之上。当前"组织者单录 + 所有用户可读写"的模式，段位一上线必然被刷分击穿。这是不可跳过的 P0。

2. **ELO 段位引擎 + 全国榜（核心增长钩子）**
   理由：把"胜+2/负+1 的积分榜"升级为有段位目标、有升降级、有球王称号的体系，直接对标王者荣耀验证过的留存机制；且竞品普遍只做胜率榜，存在明确差异化空位。

3. **F8 个人主页 / 数据中心（数据沉淀载体）**
   理由：段位、地区称号、成长曲线、成就都需要一个"我的"页面承载；它同时把排行榜的姓名弹窗升级为可探索的球员主页，是社交裂变和长期留存的支点。

> 地区榜（第四章）紧随 Top3 之后，但其 ELO、个人数据、地区字段均依赖前三项，故排在 v1.17。
